# FA German — Backend (Flask)

Минимален Flask API, който ще расте стъпка по стъпка. Използва app factory
pattern, за да е лесно добавянето на нови blueprint-и (новини, отбори,
админ и т.н.) без да се пипа съществуващият код.

## Локално стартиране

```bash
cd backend
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

API-то тръгва на `http://127.0.0.1:5000`. При първото стартиране се
създава `fagerman.db` (SQLite) автоматично.

## Налични endpoint-и

| Метод | Път                  | Описание                                   |
|-------|----------------------|---------------------------------------------|
| GET   | /api/health           | Проверка дали API-то работи                |
| POST  | /api/registration      | Записва заявка от регистрационната форма   |
| GET   | /api/registration      | Списък с всички заявки (изисква вход)      |
| GET   | /api/news              | Публикувани статии (`?limit=`, `?offset=`) |
| GET   | /api/news/<slug>       | Една публикувана статия с пълен текст      |
| GET/POST | /api/admin/news     | Всички статии (с чернови) / нова статия    |
| GET/PATCH/DELETE | /api/admin/news/<id> | Четене / редакция / изтриване     |
| GET   | /news, /news?page=2    | Страница „Всички новини“ (12 на страница)  |
| GET   | /news/<slug>           | Страница на статията (с Open Graph тагове) |
| POST  | /api/admin/uploads     | Качване на снимка (`image`): смалява се до 1600 px + 800 px версия, записва се като JPEG |
| GET   | /uploads/<файл>        | Качените снимки (дълъг кеш)                |

Снимките се пазят в `UPLOAD_DIR` (по подразбиране `backend/uploads/`, извън git).
Тази папка трябва да влиза в бекъпа и да не се трие при deploy.

Новините: `title`, `excerpt`, `body` (HTML от редактора, чисти се на сървъра),
`category`, `cover_image`, `youtube_url` (само YouTube линк), `status`
(`draft` / `published`). Адресът (`slug`) се създава от заглавието при
създаване и не се променя, за да не се чупят вече споделени линкове.

### POST /api/registration — очаквани полета

Съвпадат с имената на input полетата в `registrationForm` от index.html:
`child`, `age`, `parent`, `phone`, `email`, `message`.

Приема `application/json` или стандартен form submit
(`application/x-www-form-urlencoded`).

## Вход и акаунти (админ панел)

Роли: **owner** (главен администратор) и **coach** (треньор). Треньорите
работят само с инструментите (записвания, новини); само главният
администратор вижда страница „Потребители“ и създава/изключва/трие акаунти
и задава пароли (няма възстановяване по имейл).

Първи старт (или нов сървър) — създаване на главния администратор:

```bash
cd backend
flask --app run create-owner rosen --name "Росен"   # пита за парола
flask --app run reset-password rosen                 # забравена парола
flask --app run list-users
```

| Метод | Път | Кой |
|-------|-----|-----|
| POST | /api/auth/login, /api/auth/logout | всеки / логнат |
| GET | /api/auth/me | логнат |
| GET/POST | /api/admin/users | само owner |
| PATCH/DELETE | /api/admin/users/<id> | само owner (само треньори) |

Защитено с вход: `/api/registration` (GET/PATCH/notify), `/api/admin/*`,
`/api/admin/uploads` и всички `admin*.html` страници (без `admin-login.html`).
Публични остават `POST /api/registration`, новините и `/uploads/`.

Сигурност: хеширани пароли, сесийна cookie (HttpOnly, SameSite=Lax), CSRF
токен за всяка променяща заявка, заключване на акаунт за 15 мин. след 5
грешни паролата, спиране/смяна на парола прекратява отворените сесии.
**Production (.env):** `SECRET_KEY=<дълъг случаен низ>` и
`SESSION_COOKIE_SECURE=1` (само https; без SECRET_KEY приложението не стартира).

## Имейл уведомления към родителите

Настройките са в environment променливи (или в `backend/.env`, копирай от `.env.example`):
`MAIL_SERVER`, `MAIL_PORT`, `MAIL_USE_SSL`, `MAIL_USE_TLS`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM`.
Ако `MAIL_SERVER` е празен, имейлът само се записва в лога (тестов режим) и не се изпраща.
Шаблонът на текста е във `app/mailer.py` (`build_trial_training_email`).


## Магазин (стъпка 1: артикули)

Админ меню „Магазин“ (само главен админ и главен треньор): артикули с име, снимка, размери
(детски 116–176, възрастни XS–XXL, и двете или един размер), цена по група размери,
персонализация (име и номер) с доплащане (по подразбиране 5 €), изчерпани размери,
видимост и подредба. Цените се пазят в евроцентове.

| Метод | Път | Описание |
|-------|-----|----------|
| GET/POST | /api/admin/shop/products | Всички артикули / нов артикул |
| PATCH/DELETE | /api/admin/shop/products/<id> | Промяна / изтриване (трие и снимката) |
| POST | /api/admin/shop/products/<id>/move | `{"direction": "up"|"down"}` — подредба |

Първоначално зареждане от таблицата (безопасно за повторно пускане — съществуващите артикули не се презаписват,
но ако им липсва снимка, а вече я има в папката, тя се добавя):

```bash
flask --app run import-products items-list.xlsx --images папка_със_снимки          # само преглед
flask --app run import-products items-list.xlsx --images папка_със_снимки --apply  # запис
```


## Магазин (стъпки 2–3: публичен магазин и поръчки)

- `/shop` — мрежа от артикули, избор на размер (цена по група размери), количка в браузъра.
- „Поръчай“ → форма (имена, имейл, телефон, получаване: от академията / доставка до адрес — адресът не е задължителен,
  отметка за Политиката за лични данни) → „Изпрати поръчка“.
- `POST /api/shop/orders` — цените се смятат наново на сървъра; поръчката се записва (таблици `orders`, `order_items`,
  номер `ДДММГГ-001`, пореден за деня) и тръгват два имейла: потвърждение до клиента и известие до главния треньор
  (отговорът на имейла отива при клиента). Ако пощата не работи, поръчката остава записана
  (`coach_notified` / `customer_notified` показват дали имейлите са изпратени).
- Защита от спам: скрито поле и ограничение (по подразбиране 5 поръчки за 10 минути от един адрес).
- `/privacy` — страница за политиката за лични данни с **временен текст** (заменете го с утвърдения).

Настройки в `backend/.env`: `SHOP_ORDER_EMAIL` (къде пристигат поръчките; ако е празно — `MAIL_REPLY_TO`, после `MAIL_FROM`),
по желание `SHOP_ORDER_LIMIT` и `SHOP_ORDER_WINDOW_SECONDS`. Без `MAIL_SERVER` имейлите само се печатат в журнала.


## Магазин (стъпка 4: персонализация)

Артикул с включена „персонализация“ (админ „Магазин“) предлага в прозореца на артикула отметка
„Добави име и номер (+X €)“. Име: само латиница (A–Z, интервал, точка, апостроф, тире), до 14 знака, записва се с ГЛАВНИ
букви; номер: 1–99. Може само име или само номер. Доплащането е на брой и се добавя към цената на реда.
Един и същ артикул и размер с различно име/номер са отделни редове в количката и в поръчката.
Надписът се вижда в количката, в обобщението, в двата имейла и се пази в `order_items`
(`personal_name`, `personal_number`, `personalization_fee_cents`).


## Магазин (стъпка 5: админ „Поръчки“)

Меню „Поръчки“ (главен админ и главен треньор; значка с броя на новите): списък с най-новите първи, филтър по статус
(нова → обработена → предадена / отказана), търсене по номер, име, телефон и имейл. Всяка поръчка се отваря за подробности:
артикули с размери и персонализация, данни и начин на получаване, дата на съгласието за лични данни, бележка за админите,
състояние на двата имейла с бутон „Изпрати отново“ (поръчките, за които имейлът до треньора не е тръгнал, са отбелязани
в червено). Изтриване на поръчка (заедно с личните данни на клиента) — само главният админ.

| Метод | Път | Описание |
|-------|-----|----------|
| GET | /api/admin/shop/orders?status=&q= | Списък + брой по статуси |
| GET | /api/admin/shop/orders/summary | `{"new": n}` за значката в менюто |
| PATCH | /api/admin/shop/orders/<id> | `{"status", "admin_note"}` |
| POST | /api/admin/shop/orders/<id>/resend | `{"to": "coach" \| "customer"}` |
| DELETE | /api/admin/shop/orders/<id> | Само главен админ |


## Магазин (стъпка 6: отчети, CSV, почистване)

Страница „Отчети и експорт“ (бутон в „Поръчки“; главен админ и главен треньор):
- **Период** по календарни дни по софийско време (от/до; бързи избори: този месец, миналия месец, последните 30 дни,
  тази година, всичко).
- **Оборот** (по избор: само обработени и предадени, или всички без отказаните), брой поръчки по статуси, средна поръчка,
  продадени бройки, сума на още необработените нови поръчки.
- **Най-продавани артикули** (брой, сума, колко от тях са с надпис).
- **CSV експорт** за периода: `;` за разделител, UTF-8 с BOM, десетична запетая — отваря се директно в български Excel.
  Един ред за всеки артикул; общата сума е само на първия ред на поръчката. Клетки, започващи с `= + - @`, се предхождат
  от апостроф (защита от формули в Excel).
- **Изтриване на стари поръчки** (само главен админ): избор на срок 3 / 6 / 12 / 24 месеца, преглед на броя, бутон за CSV
  на тези поръчки и изтриване след потвърждение (сървърът отказва, ако броят се е променил след прегледа).

| Метод | Път | Описание |
|-------|-----|----------|
| GET | /api/admin/shop/reports/stats?from=&to=&scope= | Статистика (`scope=confirmed\|all`) |
| GET | /api/admin/shop/orders/export?from=&to= | CSV файл |
| GET | /api/admin/shop/orders/purge-preview?months=12 | Колко поръчки са по-стари (главен админ) |
| POST | /api/admin/shop/orders/purge | `{"months": 12, "expected": n}` (главен админ) |

Новата зависимост `tzdata` (в `requirements.txt`) осигурява часовата зона Europe/Sofia на Windows:
`pip install -r requirements.txt`.

## Футболисти и родителски портал (стъпка 1)

Нови таблици: `parent_accounts` (родителски акаунт, потребителско име = имейл) и `players` (профил на дете).
Колоната `registrations.player_id` се добавя автоматично при стартиране.

| Метод | Път | Кой |
|-------|-----|-----|
| GET | /api/admin/players | главен админ, главен треньор (всички); треньор — само отборите си, само четене |
| POST/PATCH | /api/admin/players[/<id>] | главен админ, главен треньор |
| POST | /api/admin/players/<id>/new-password | главен админ, главен треньор (паролата отива по имейл) |
| POST | /api/admin/players/<id>/archive, /restore | главен админ, главен треньор |
| DELETE | /api/admin/players/<id>[?forever=1] | архивира; `forever` — само главен админ, само архивиран |
| GET | /api/admin/registrations/<id>/prefill | данни от запитването за „Създай профил“ |
| POST | /api/parent/login, /logout, /change-password | родител |
| GET | /api/parent/me, /children | родител |

Родителският вход е отделен от админ входа (други ключове в сесията, друг CSRF токен); страниците
`parent*.html` са достъпни само за влезли родители. Временната парола изтича след 7 дни, смяната ѝ е
задължителна, заедно със съгласието с Политиката за поверителност при първия вход.
Проверка: `python backend/tests/test_players.py`.

## Документи за картотекиране (стъпка 2)

Комплектът на детето за сезона се отваря автоматично: **до 14 г.** — заявление, декларация, акт за раждане,
снимка, медицинско; **14–18 г. и 18+** — заявление, декларация, лична карта (двете страни), снимка, медицинско.
Категорията е по U числото за сезона (до U13 / U14–U17 / U18+). Родителят качва снимки или PDF (до 5 файла
и 20 MB на документ) и натиска „Изпрати за проверка“; главният треньор одобрява или връща с коментар.
„Картотеката е получена“ изтрива качените файлове. Архивирането на детето също ги изтрива.

Файловете са **шифровани** (Fernet) в `DOCS_DIR` (по подразбиране `backend/documents/`, извън git и извън
публичните папки) и се четат само през проверени адреси. В production е задължителен `DOCS_KEY` в `.env`:
`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
**Ключът и папката трябва да са в бекъпа** — без ключа файловете не могат да се прочетат. Без `DOCS_KEY`
(само локално) се създава `documents/dev.key`.

Празните бланки на БФС са в `backend/bfs_templates/` (оригинални; при промяна от БФС се подменя само файлът).
Проверка: `python backend/tests/test_documents.py`.
